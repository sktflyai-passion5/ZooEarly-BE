# 화면 ↔ API 매핑

와이어프레임의 어떤 버튼이 어떤 백엔드 API를 부르는지 정리한 문서다.
기준 시안: `hifi/` (홈 · 등교 · 수업시간 · 급식시간 · 하교시간)

---

## 먼저 알아야 할 것

**대부분의 버튼은 API를 부르지 않는다.** 시나리오 문장·선택지·진행 상태는 전부 앱 번들과
앱 로컬 저장소에 있다 (명세 §0.2 — 서버는 무상태다).

서버를 부르는 순간은 **딱 세 가지뿐**이다.

| 언제 | 무엇을 |
|---|---|
| 🎤 **첫 녹음이 끝났을 때** (② 화면) | `POST /stt` → `POST /feedback` (2회 연속) |
| 🔊 **스피커 아이콘을 탭했을 때** | `POST /tts` |
| (자유 대화 화면이 생기면) | `POST /chat` |

나머지 버튼 — `다음`, `홈으로 돌아가기`, 선택지 탭, 시나리오 카드 — 은 **전부 화면 전환**이다.

---

## 공통 흐름 (등교 · 수업시간 · 급식시간 · 하교시간 동일)

```
① 시나리오 인트로            [말해보기]  [선택해보기]        API 없음
        │
        ├─ 말해보기 ──▶ ② 🎤 녹음 화면
        │                    "마이크를 누르고 말해보세요"
        │                    녹음 종료 ──▶ POST /stt ──▶ POST /feedback   ★
        │
        └─ 선택해보기 ─▶ ②' 표현 고르기
                             "어떤 표현을 사용해볼까요?"
                             선택지 3개 · [다른 표현 보기]   API 없음
        │
③ 피드백 배너                "잘했어! 무슨 말인지 이해했어."     API 없음
                             (②에서 받은 /feedback 응답을 그림)
        │
④ 자연스러운 표현            "이렇게 말하면 더 자연스러워요"
     ┌ 화면에 뜨는 문장은 ②에서 받은 /feedback 응답이다. 여기서 새로 받지 않는다
     │    한국어 = naturalSentence,  모국어 = translation
     │
     🔊 [한국어 문장]  ──────▶ POST /tts { language: "KOREAN" }        ★ 탭했을 때만
     "이 말의 뜻이에요!"
     🔊 [모국어 번역]  ──────▶ POST /tts { language: <nativeLanguage> } ★ 탭했을 때만
                             [다음]                          API 없음
        │
⑤ 따라 말하기                "이제 따라 말해볼까요?"
     ┌ 따라 말할 문장 = ④의 naturalSentence. 역시 새로 받지 않는다
     │
     🔊 [문장 상자]    ──────▶ POST /tts { language: "KOREAN" }        ★ 탭했을 때만
     🎤 녹음           ──────▶ API 없음 ★★ 연습 전용 — 채점하지 않는다
                             녹음한 음성을 서버로 보내지 않는다
                             [다음]                          API 없음
        │
⑥ 완료 화면                  [홈으로 돌아가기]                API 없음
```

★ 표시가 서버를 부르는 지점이다. 화면 6개 중 **3개에서만** 부른다.

**🎤 마이크가 두 번 나오지만 서버를 부르는 건 ②뿐이다.** ⑤의 마이크는 연습용이라
녹음한 음성을 서버로 보내지 않는다. 마이크가 보인다고 `/stt`를 부르면 안 된다.

## 버튼별 표

### 홈 · 온보딩

| 화면 | 버튼 / 동작 | API | 비고 |
|---|---|---|---|
| 온보딩 | 닉네임 입력 | — | 앱 로컬 저장. 이후 **모든** `/chat`·`/feedback` 요청에 `nickname`으로 실린다 |
| 온보딩 | 모국어 선택 | — | 앱 로컬 저장. `nativeLanguage`로 실린다 |
| 온보딩 | `완료` | — | 저장 후 화면 전환 |
| 오늘의 학교 연습 | 시나리오 카드 4개 | — | 선택만 |
| 오늘의 학교 연습 | `연습 시작` | — | 화면 전환 |

> 온보딩 값이 **서버로 바로 가지 않는다.** 앱이 갖고 있다가 요청할 때마다 실어 보낸다.
> 서버는 사용자를 저장하지 않는다 (명세 §0.1 — DB 없음).

### 시나리오 진행

| 화면 | 버튼 / 동작 | API | 요청에 실리는 것 |
|---|---|---|---|
| 인트로 | `말해보기` | — | |
| 인트로 | `선택해보기` | — | 선택지는 앱 번들 데이터 |
| 표현 고르기 | 선택지 1·2·3 | — | 고른 문장이 `targetSentence`가 된다 |
| 표현 고르기 | `다른 표현 보기` | — | 앱 번들 안에서 교체 |
| 🎤 녹음 | **녹음 종료** | **`POST /stt`** | `audio`, `language`(BCP-47, 예 `ko-KR`) |
| 🎤 녹음 | (이어서) | **`POST /feedback`** | `targetSentence`, `recognizedText`(= stt 결과), `nickname`, `nativeLanguage`, `scenario` |
| 피드백 배너 | — | — | `/feedback` 응답의 `title`·`body`를 그린다 |
| 자연스러운 표현 | (화면 진입) | — | **문장은 ②의 `/feedback` 응답에서 온다.** 새로 부르지 않는다 |
| 자연스러운 표현 | 🔊 **한국어 상자** | **`POST /tts`** | `text`= `naturalSentence`, `language`=`"KOREAN"` |

| 자연스러운 표현 | `다음` | — | |
| 따라 말하기 | (화면 진입) | — | 따라 말할 문장 = ④의 `naturalSentence` |
| 따라 말하기 | 🔊 **문장 상자** | **`POST /tts`** | `text`= `naturalSentence`, `language`=`"KOREAN"` |
| 따라 말하기 | 🎤 **녹음** | **— (없음)** | **연습 전용이라 채점하지 않는다.** 녹음을 서버로 보내지 않는다 |
| 따라 말하기 | `다음` | — | |
| 완료 | `홈으로 돌아가기` | — | |

### 수업시간 전용 화면

| 화면 | 버튼 / 동작 | API | 비고 |
|---|---|---|---|
| 책 페이지 넘기기 | 손가락 스와이프 | — | 앱 로컬 |
| `15페이지! 잘 찾았어요` | `다음` | — | |

| 피드백 | `다시 읽기` | — | 시 읽기 화면으로 되돌아간다. 다시 녹음하면 `/stt` → `/feedback`을 **한 번 더** 부른다 |

## 호출 상세

### 🎤 녹음 종료 — 2회 연속 (② 화면에서만)

**녹음 중에는 아무것도 부르지 않는다.** 녹음이 끝난 뒤 두 번, **순차로** 부른다.
두 번째가 첫 번째의 결과를 필요로 하므로 동시에 보내면 안 된다.

```
녹음 종료
   │
   ├─① POST /stt        "뭐라고 말했는지 알려줘"
   │       ↓ 응답을 기다린다
   └─② POST /feedback   "그게 목표 문장과 맞았는지 봐줘"
```

**① 음성 → 텍스트**

```http
POST /api/v1/ai/stt        Content-Type: multipart/form-data

audio    : <녹음 파일>     m4a / wav / webm, 최대 10MB · 60초
language : "ko-KR"         선택. BCP-47 자유 문자열. 생략 시 ko-KR
```
```json
200 OK
{ "success": true, "data": { "text": "안녕 나도 만나서 반가와", "confidence": 0.92 } }
```

`confidence`는 **화면에 표시하지 않는다** (명세 §3). 아이에게 점수를 보여주지 않기 위해서다.

**② 채점 + 피드백**

```http
POST /api/v1/ai/feedback   Content-Type: application/json
```
```json
{
  "targetSentence" : "안녕 나도 만나서 반가워!",
  "recognizedText" : "안녕 나도 만나서 반가와",
  "nickname"       : "민수",
  "scenario"       : "ARRIVAL",
  "nativeLanguage" : "VIETNAMESE"
}
```

| 필드 | 필수 | 무엇을 넣나 |
|---|---|---|
| `targetSentence` | ✅ | 아이가 말했어야 할 문장 (고른 선택지 또는 스텝 문장) |
| `recognizedText` | ✅ | ①의 `text`. **`null`도 그대로 넣는다** |
| `nickname` | ✅ | 온보딩 값 |
| `scenario` | — | 시나리오 enum |
| `nativeLanguage` | — | 언어 enum. 없으면 `translation`이 `null`로 온다 |

**① 결과별 분기**

| ①의 결과 | 어떻게 하나 |
|---|---|
| `text: "..."` | 그대로 ②로 |
| **`text: null`** | **에러가 아니다.** `recognizedText: null`로 ②를 부른다 → 격려 피드백이 온다 |
| `422 STT_FAILED` | STT 엔진 장애. **②를 부르지 않고** "괜찮아, 다시 해볼까?" 폴백 |
| `502` / `504` | 서버 장애. 위와 동일 |

`null`과 `422`는 다르다. **`null`은 "못 알아들었다"(정상), `422`는 "엔진이 죽었다"(장애)** 다.

**대기 화면이 필요하다.** 각 15초 타임아웃이라 최악의 경우 30초가 걸린다.
시안의 "듣고 있어요" 화면이 그 자리다.

**채점은 앱이 한다.** `/feedback`은 판정 재료(`matched`, `understood`)만 준다.
별점 계산과 진행 상태 저장은 앱 로컬이다 (명세 §5 설계 계약 3).

### 🔊 스피커 탭 — 1회

```http
POST /api/v1/ai/tts        Content-Type: application/json
```
```json
{ "text": "안녕 나도 만나서 반가워!", "language": "KOREAN" }
```
```json
200 OK
{ "success": true, "data": { "audio": { "data": "SUQzBAAA...", "format": "mp3" } } }
```

`voice`(`TEACHER`/`FRIEND`)와 `speed`(0.5~1.5)는 생략 가능하다.
생략 시 `TEACHER` / `0.9` — 아동용으로 느리게 읽는다.

`data`는 base64 mp3다. 디코딩해서 재생한다.

## 음성은 왜 서버에서 받나

`react-native-tts` 같은 **기기 내장 TTS를 쓰면 안 된다.** 이유가 하나 있다.

이 앱은 **모국어도 읽어줘야 한다.**

```
🔊 [ 많이 주세요. ]              한국어 — 대부분 기기에 있다
🔊 [ Cho mình nhiều nhé. ]       베트남어 — 언어팩이 없으면 무음이다
```

베트남어·중국어 TTS 엔진이 기기에 깔려 있지 않으면 **아무 소리도 안 난다.**
아이가 설정에 들어가 언어팩을 받을 수도 없다. **두 상자 중 모국어 쪽만 안 되는 앱**이 된다.

부차적으로 OS 기본 음성은 기계적이라, 아동용으로 느리게 읽고
`TEACHER`/`FRIEND` 톤을 나누는 설계와도 맞지 않는다.

### 대신 캐시가 전제다

명세 §4가 이미 요구한다 — 같은 문장을 두 번 이상 재생할 때 서버에 다시 묻지 않는다.
스텝 문장은 고정 텍스트라 적중률이 높다. 키는 `text + language + voice + speed`면 충분하다.

### 재생에 맞춰 글자를 강조하고 싶다면

서버가 주는 건 mp3뿐이라 **단어별 타이밍 정보가 없다.** 대신 이렇게 하면 된다.

| 원하는 것 | 방법 | 서버 변경 |
|---|---|---|
| 틀린 어절 강조 | `/feedback`의 `highlightWords`를 칠한다 | 없음 (이미 있다) |
| 줄 단위로 따라 켜기 | **줄마다 `/tts`를 나눠 부르고 순차 재생**한다 | 없음 |
| 단어 단위 | 글자 수 비례로 근사하거나, 고정 문장이니 타이밍을 미리 만들어 번들에 넣는다 | 없음 |

수업시간의 시(詩)처럼 여러 줄인 경우 **줄 단위 분할이 잘 맞는다.** 지금 재생 중인
오디오가 몇 번째 줄인지 앱이 정확히 알게 되므로 정렬도 추정도 필요 없다.
시는 고정 텍스트라 한 번 받으면 캐시되어 두 번째부터는 지연이 없다.

## 주의할 점 5가지

### ① `/tts`의 `language`는 필수다 (v1.3.0~)

한국어를 읽을 때도 `"KOREAN"`을 명시해야 한다. 🔊 버튼 **전부** 해당한다 —
피드백 화면 두 상자뿐 아니라 따라 말하기 화면, 수업시간의 시 읽기도 마찬가지다.
빼면 `400 INVALID_PARAMETER` (field: `language`).

### ② `nickname`은 필수다 (v1.1.0~)

`/chat`과 `/feedback`을 부를 때 온보딩에서 받은 닉네임을 함께 보낸다.
빼면 `400 INVALID_PARAMETER` (field: `nickname`).

### ③ 마이크가 있다고 다 `/stt`를 부르는 게 아니다

시나리오 하나에 마이크 화면이 **두 번** 나오는데, 서버를 부르는 건 **앞의 하나뿐**이다.

| 화면 | 무엇을 하나 | API |
|---|---|---|
| ② 🎤 첫 녹음 | 아이가 스스로 답해본다 → **채점하고 피드백을 준다** | `/stt` → `/feedback` |
| ⑤ 🎤 따라 말하기 | 교정된 문장을 **연습만 한다** | **없음** |

⑤에서 채점하지 않는 이유는 흐름을 보면 알 수 있다. 이미 ②에서 채점했고,
⑤는 "이렇게 말하면 더 좋아요"를 몸에 익히는 단계다. 여기서 또 틀렸다고 하면
아이가 같은 문장으로 두 번 평가받는 셈이 된다.

### ④ 인식 실패는 에러가 아니다

아이가 우물거려서 못 알아들으면 `/stt`가 **`200` + `text: null`** 을 준다.
이때도 `/feedback`을 그대로 부른다 — `recognizedText: null`이 유효한 값이고,
"괜찮아, 다시 해볼까?" 류의 격려 피드백이 돌아온다 (명세 §5 설계 계약 1).

422(엔진 장애)와는 다르다 — 분기표는 위 **호출 상세** 참고.

### ⑤ 화면에 뜨는 문장과 재생되는 음성은 출처가 다르다

혼동하기 쉬운 지점이다.

| | 어디서 | 언제 |
|---|---|---|
| **문장(텍스트)** | `/feedback` 응답 | 🎤 녹음이 끝났을 때 이미 받아둔 것 |
| **음성(mp3)** | `/tts` 응답 | 🔊를 **탭한 그 순간** |

`/feedback`은 문장만 준다 — 음성은 안 준다.
`/tts`는 음성만 준다 — 번역도 교정도 하지 않는다.

그래서 "자연스러운 표현" 화면은 **들어올 때는 API를 안 부르고**, 🔊를 탭할 때만 부른다.

## 지금 쓰이지 않는 API — `/chat`

**목업 5개 어디에도 `/chat`을 부르는 화면이 없다.**

`/chat`은 자유 대화용이다 — 아이가 무슨 말을 할지 모를 때 STT + LLM + TTS를 한 번에 돌린다.
지금 시안은 전부 "정해진 문장 따라 말하기"라 `/stt` + `/feedback` 조합만 쓴다.

명세 §7에는 자유 대화 화면이 있는 것으로 되어 있다. 둘 중 하나다.

- 자유 대화 화면이 **아직 안 그려진 것** → 그리면 `/chat`을 쓴다
- 설계가 바뀌어 **자유 대화를 빼기로 한 것** → `/chat`은 당분간 안 쓰인다

**기획 쪽에 확인이 필요하다.** 게이트웨이에는 이미 구현돼 있어 언제 붙여도 된다.

## 와이어프레임에 표기하는 방법

시안 이미지에 긴 설명을 넣으면 읽기 어렵다. **번호만 달고 이 문서를 참조**하는 편이 낫다.

```
화면 옆에:   ★ POST /stt → /feedback
             ★ POST /tts (KOREAN)
```

Figma를 쓴다면 각 버튼에 **코멘트**로 API 이름만 달고, 상세는 이 문서 링크를 건다.
요청 필드가 바뀌면 이 문서만 고치면 되고 시안은 그대로 둘 수 있다.
