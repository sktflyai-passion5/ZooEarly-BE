# 화면 ↔ API 매핑

와이어프레임의 어떤 버튼이 어떤 백엔드 API를 부르는지 정리한 문서다.
기준 시안: `hifi/` (홈 · 등교 · 수업시간 · 급식시간 · 하교시간)

---

## 먼저 알아야 할 것

**대부분의 버튼은 API를 부르지 않는다.** 시나리오 문장·선택지·진행 상태는 전부 앱 번들과
앱 로컬 저장소에 있다 (명세 §0.2 — 서버는 무상태다).

서버를 부르는 순간은 **네 가지**다.

| 언제 | 무엇을 |
|---|---|
| 🎤 **첫 녹음이 끝났을 때** (② 화면) | `POST /stt` |
| **`선택해보기`로 표현 고르기 화면에 들어갈 때** (②' 화면) | `GET /pronunciation/sentences` |
| 🎤 **따라 말하기 녹음이 끝났을 때** (⑤ 화면) | `POST /pronunciation` |
| 🔊 **스피커 아이콘을 탭했을 때** | `POST /tts` — 단 **캐시에 있으면 부르지 않는다** |
| ~~표현 교정~~ | ~~`POST /feedback`~~ — **현재 구현하지 않는다** |
| ~~자유 대화~~ | ~~`POST /chat`~~ — **현재 쓰이는 화면이 없다** |

나머지 버튼 — `다음`, `홈으로 돌아가기`, 선택지 탭(고른 뒤), 시나리오 카드 — 은 **전부 화면 전환**이다.
선택지 자체(문장 3개)는 화면 전환이 아니라 **위에서 미리 받아둔 데이터를 보여주는 것**이다.

★ 표시가 서버를 부르는 지점이다.

> **`말해보기`(자유 발화) 경로는 현재 미구현이다** (기획 확인 완료, 2026-08-24). 화면만
> 있고 그 뒤로 이어지는 로직이 없다. `/pronunciation`이 `sentenceId`를 요구하게 되면서
> 이 경로엔 애초에 넘길 값이 없었는데, 그 상태 그대로 두기로 확정됐다 — 나중에
> 구현하게 되면 그때 다시 설계한다.

**🎤 마이크가 두 번 나오는데 부르는 API가 다르다.**

| | 무엇을 보나 | API |
|---|---|---|
| ② 첫 녹음 | 뭐라고 말했나 (텍스트) | `/stt` |
| ⑤ 따라 말하기 | 어떻게 **발음**했나 (오디오) | `/pronunciation` |

⑤는 STT를 거치지 않는다. 발음은 텍스트로 알 수 없기 때문이다.

**②의 `/stt` 결과는 지금 화면에 쓰이지 않는다.** 원래는 그 텍스트로 `/feedback`을
불러 ③④를 그렸는데, 표현 교정을 구현하지 않기로 하면서 갈 곳이 없어졌다.
호출 자체를 빼도 되고, 나중을 위해 남겨둬도 된다 — 앱 판단이다.

> ### 시 읽기는 등교·급식·하교와 같은 경로를 그대로 쓴다 (2026-08-24 확정)
>
> FastAPI의 `GET /pronunciation/sentences`에 `category: "study"`인 `study_1`이
> 추가됐다. `text`는 시 전체("노란 꽃이 피었어요. 예쁜 꽃이 피었어요. 바람이
> 살랑살랑 꽃이 웃어요.")가 한 항목에 이어져 있다.
>
> **이전 우려(별도 낭독 엔드포인트가 필요할 것)는 해소됐다.** `study_1`도 다른
> 9개와 똑같은 `sentenceId`라서, ⑤ 따라 말하기와 똑같이 `POST /pronunciation`을
> 그대로 호출하면 된다 — `/internal/v1/feedback/reading`을 기다릴 필요가 없다.
>
> ```json
> { "sentenceId": "study_1",
>   "sentence": "노란 꽃이 피었어요. 예쁜 꽃이 피었어요. 바람이 살랑살랑 꽃이 웃어요.",
>   "targetWord": "살랑살랑", "targetIndex": 5, "targetZ": -1.82,
>   "words": [ "... 시 전체 어절", { "word": "살랑살랑", "z": -1.82, "warn": true, "worstPhone": null } ] }
> ```
>
> 시안의 `"살랑살랑" 부분을 조금 더 천천히 읽어볼까요?` 는 이 `targetWord`를
> 그대로 문구에 넣은 것이다. `words`가 시 전체 어절을 담으므로 다른 카테고리보다
> 배열이 길다 — 화면 배선(빈칸 만들기 등)은 동일하게 처리하면 된다.
>
> **"표현 고르기" 화면과 다른 점 하나**: 등교/급식/하교는 3개 중 하나를 아이가
> **고르지만**, `study`는 1개뿐이라 고르는 UI가 없다. 시 읽기 화면 진입 시
> `category === "study"`인 항목을 바로 쓰면 된다.

## 호출 상세

### 🎤 ② 첫 녹음 — `/stt` 1회

**녹음 중에는 아무것도 부르지 않는다.** 끝난 뒤 한 번 부른다.

> 원래는 `/stt` → `/feedback` 2회 연속이었다. 표현 교정을 구현하지 않기로 해서
> `/feedback`이 빠졌고, `/stt` 결과를 쓸 화면도 없어졌다.
> 호출 자체를 빼도 되고 나중을 위해 남겨둬도 된다 — 앱 판단이다.

```http
POST /api/v1/ai/stt        Content-Type: multipart/form-data

audio    : <녹음 파일>     m4a / wav / webm, 최대 10MB · 30초
language : "ko-KR"         선택. BCP-47 자유 문자열. 생략 시 ko-KR
```
```json
200 OK
{ "success": true, "data": { "text": "안녕 나도 만나서 반가와", "confidence": 0.92 } }
```

`confidence`는 **화면에 표시하지 않는다** (명세 §3). 아이에게 점수를 보여주지 않기 위해서다.

**결과별 분기**

| 결과 | 어떻게 하나 |
|---|---|
| `text: "..."` | 다음 화면으로 |
| **`text: null`** | **에러가 아니다.** 못 알아들었을 뿐이니 그대로 진행한다 |
| `422 STT_FAILED` | STT 엔진 장애. "괜찮아, 다시 해볼까?" 폴백 |
| `502` / `504` | 서버 장애. 위와 동일 |

`null`과 `422`는 다르다. **`null`은 "못 알아들었다"(정상), `422`는 "엔진이 죽었다"(장애)** 다.

**대기 화면이 필요하다.** 타임아웃이 15초다. 시안의 "듣고 있어요" 화면이 그 자리다.

### 🎤 표현 고르기 진입 — `/pronunciation/sentences` 1회 (②' 화면, 선택해보기 경로만)

```http
GET /api/v1/ai/pronunciation/sentences
```
```json
200 OK
{ "success": true, "data": [
    { "sentenceId": "arrival_1", "category": "arrival", "text": "안녕 나도 만나서 반가워 !" },
    { "sentenceId": "arrival_2", "category": "arrival", "text": "안녕! 우리 친하게 지내자" },
    { "sentenceId": "arrival_3", "category": "arrival", "text": "안녕 잘 부탁해 !" },
    { "sentenceId": "study_1", "category": "study", "text": "노란 꽃이 피었어요. 예쁜 꽃이 피었어요. 바람이 살랑살랑 꽃이 웃어요." },
    { "sentenceId": "lunch_1", "category": "lunch", "text": "조금만 주세요." },
    "... (급식 2개, 하교 3개 생략, 총 10개)"
  ] }
```

10개를 한 번에 받아서 `category`로 걸러 화면에 맞는 것만 보여준다 — 등교/급식/하교는
3개(고르는 화면), 수업시간(`study`)은 1개(고를 것 없이 바로 씀). 시나리오마다
따로 부르지 않는다. 아이가 하나를 고르면(또는 `study`처럼 자동으로 정해지면) 그
`sentenceId`를 들고 있다가 ⑤에서 그대로 다시 쓴다.

### 🎤 ⑤ 따라 말하기 녹음 — `/pronunciation` 1회

```http
POST /api/v1/ai/pronunciation   Content-Type: multipart/form-data

audio      : <녹음 파일>   m4a / wav / webm, 최대 10MB · 30초
sentenceId : <선택한 값>   ②'(또는 시 읽기)에서 받은 10개 중 하나. 자유 텍스트가 아니다
```
```json
200 OK
{ "success": true, "data": {
    "sentenceId": "arrival_2", "sentence": "안녕! 우리 친하게 지내자",
    "targetWord": "지내자", "targetIndex": 2, "targetZ": -1.82,
    "words": [ { "word": "지내자", "z": -1.82, "warn": true, "worstPhone": "ㄴ" } ] } }
```

**STT를 거치지 않는다.** 발음은 텍스트로 알 수 없어서 녹음을 그대로 보낸다.

**잘함/못함 판정은 FastAPI가 한다** (v1.5.0부터). `targetWord`가 **`null`이면 발음
전부가 기준(z ≥ -1.5) 이상**이라는 뜻이다 — 퀴즈 화면 없이 바로 [발음1] 칭찬 화면으로
간다. `null`이 아니면 [발음2] 퀴즈로 간다. 앱은 이 값을 보고 분기만 하면 되고,
z점수로 직접 판정할 필요가 없다.

**빈칸 문장은 서버가 안 준다.** `quizSentence` 필드가 v1.5.0에서 빠졌다. `sentence`를
공백으로 나눠 `targetIndex`번째를 빈칸으로 바꾸는 건 앱이 한다.

**빈칸은 `targetWord` 하나만** 쓴다. `warn`이 여러 개 켜져도 하나만 만든다.

### 🔊 스피커 탭 — 1회

```http
POST /api/v1/ai/tts        Content-Type: application/json
```
```json
{ "text": "안녕 나도 만나서 반가워!", "language": "KOREAN" }
```
```json
200 OK
{ "success": true, "data": { "audio": { "data": "SUQzBAAA...", "format": "mp3" } } }
```

`voice`(`TEACHER`/`FRIEND`)와 `speed`(0.5~1.5)는 생략 가능하다.
생략 시 `TEACHER` / `0.9` — 아동용으로 느리게 읽는다.

`data`는 base64 mp3다. 디코딩해서 재생한다.

## 음성은 왜 서버에서 받나

`react-native-tts` 같은 **기기 내장 TTS를 쓰면 안 된다.** 이유가 하나 있다.

이 앱은 **모국어도 읽어줘야 한다.**

```
🔊 [ 많이 주세요. ]              한국어 — 대부분 기기에 있다
🔊 [ Cho mình nhiều nhé. ]       베트남어 — 언어팩이 없으면 무음이다
```

베트남어·중국어 TTS 엔진이 기기에 깔려 있지 않으면 **아무 소리도 안 난다.**
아이가 설정에 들어가 언어팩을 받을 수도 없다. **두 상자 중 모국어 쪽만 안 되는 앱**이 된다.

부차적으로 OS 기본 음성은 기계적이라, 아동용으로 느리게 읽고
`TEACHER`/`FRIEND` 톤을 나누는 설계와도 맞지 않는다.

### 대신 캐시가 전제다

명세 §4가 이미 요구한다 — 같은 문장을 두 번 이상 재생할 때 서버에 다시 묻지 않는다.
스텝 문장은 고정 텍스트라 적중률이 높다. 키는 `text + language + voice + speed`면 충분하다.

**④와 ⑤는 같은 문장을 쓴다.** 둘 다 `naturalSentence`를 읽어주므로 캐시 키가 같고,
④에서 한 번 받으면 ⑤에서는 **호출 없이 즉시 재생**된다.

```
④ 🔊 탭  →  POST /tts  →  mp3 캐시에 저장
⑤ 🔊 탭  →  캐시 적중  →  호출 없음, 즉시 재생
```

**빈틈이 하나 있다.** ④에서 아이가 🔊를 안 눌렀으면 캐시가 비어 있어서 ⑤에서 처음
호출하게 된다. 그러면 탭하고 나서 몇 초를 기다려야 한다.

### 그래서 ④ 진입 시 미리 받아둔다 (prefetch)

**화면에 들어오는 즉시 두 문장을 미리 받아 캐시에 넣는다.**

> **미리 받아두는 것이지 미리 재생하는 것이 아니다.** 소리는 **탭했을 때만** 난다.
> 화면에 들어왔다고 저절로 나오면 안 된다. prefetch의 목적은 **탭한 뒤의 기다림을 없애는 것**이다.

문장이 짧아(200자 이하) 미리 받는 비용도 작다.

**결과를 기다리지 않는다.** 화면은 바로 그리고, 받아오는 건 뒤에서 돌린다.
실패해도 무시한다 — 아이가 탭하는 순간 어차피 다시 시도한다.

```ts
// ── TTS 캐시 ──────────────────────────────────────────
// 키에 language를 넣는다. 같은 글자라도 언어가 다르면 다른 음성이다.
// voice·speed는 기본값만 쓰므로 키에서 뺐다 — 쓰기 시작하면 키에 추가한다.
const ttsCache = new Map<string, string>();          // key → base64 mp3
const cacheKey = (text: string, language: string) => `${language}|${text}`;

async function getTts(text: string, language: string): Promise<string> {
  const key = cacheKey(text, language);
  const hit = ttsCache.get(key);
  if (hit) return hit;                                // 캐시 적중 — 서버를 부르지 않는다

  const res = await fetch(`${BASE_URL}/api/v1/ai/tts`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ text, language }),         // language는 필수다 (v1.3.0~)
  });
  const json = await res.json();
  if (!json.success) throw new Error(json.error.code);

  const mp3 = json.data.audio.data;
  ttsCache.set(key, mp3);
  return mp3;
}

// ── ④ 자연스러운 표현 화면 ─────────────────────────────
// 진입하자마자 받아만 둔다. 재생하지 않는다
useEffect(() => {
  getTts(naturalSentence, "KOREAN").catch(() => {});   // 기다리지 않는다
  if (translation) getTts(translation, nativeLanguage).catch(() => {});
}, [naturalSentence, translation]);

// 🔊 탭 — 여기서만 소리가 난다
const onSpeakerTap = async (text: string, language: string) => {
  const mp3 = await getTts(text, language);            // 캐시에 있으면 즉시
  play(mp3);
};
```

⑤ 따라 말하기 화면도 **탭했을 때** `getTts(naturalSentence, "KOREAN")`을 부른다.
④에서 이미 채워뒀으므로 캐시가 적중해 서버를 부르지 않고, 기다림 없이 바로 소리가 난다.

> 위 캐시는 앱을 껐다 켜면 사라진다. 세션 안에서는 충분하지만, 스텝 문장처럼
> 계속 반복되는 것은 파일로 저장해두면 더 낫다. 프로토타입 단계에서는 메모리로도 된다.

### 재생에 맞춰 글자를 강조하고 싶다면

서버가 주는 건 mp3뿐이라 **단어별 타이밍 정보가 없다.** 대신 이렇게 하면 된다.

| 원하는 것 | 방법 | 서버 변경 |
|---|---|---|
| 약한 어절 강조 | `/pronunciation`의 `targetWord`를 칠한다 | 없음 (이미 있다) |
| 줄 단위로 따라 켜기 | **줄마다 `/tts`를 나눠 부르고 순차 재생**한다 | 없음 |
| 단어 단위 | 글자 수 비례로 근사하거나, 고정 문장이니 타이밍을 미리 만들어 번들에 넣는다 | 없음 |

수업시간의 시(詩)처럼 여러 줄인 경우 **줄 단위 분할이 잘 맞는다.** 지금 재생 중인
오디오가 몇 번째 줄인지 앱이 정확히 알게 되므로 정렬도 추정도 필요 없다.
시는 고정 텍스트라 한 번 받으면 캐시되어 두 번째부터는 지연이 없다.

## 주의할 점 5가지

### ① `/tts`의 `language`는 필수다 (v1.3.0~)

한국어를 읽을 때도 `"KOREAN"`을 명시해야 한다. 🔊 버튼 **전부** 해당한다 —
피드백 화면 두 상자뿐 아니라 따라 말하기 화면, 수업시간의 시 읽기도 마찬가지다.
빼면 `400 INVALID_PARAMETER` (field: `language`).

### ② `nickname`은 `/chat`·`/feedback`에서 필수다 (v1.1.0~)

둘 다 **현재 미사용**이라 지금 당장 챙길 것은 없다. 나중에 그 화면을 만들 때
온보딩 닉네임을 함께 보내야 한다. 빼면 `400 INVALID_PARAMETER` (field: `nickname`).

`/stt`·`/tts`·`/pronunciation`은 `nickname`을 받지 않는다.

### ③ 마이크 두 개는 부르는 API가 다르다

시나리오 하나에 마이크 화면이 **두 번** 나오는데, **같은 API가 아니다.**

| 화면 | 무엇을 보나 | API |
|---|---|---|
| ② 🎤 첫 녹음 | 뭐라고 말했나 | `/stt` (1회) |
| ⑤ 🎤 따라 말하기 | 어떻게 **발음**했나 | `/pronunciation` (1회) |

⑤는 **STT를 거치지 않는다** — 발음을 보려면 오디오가 필요하고, 텍스트로는 알 수 없기 때문이다.

`/stt`를 두 번 부르지 않도록 주의한다.

### ④ 인식 실패는 에러가 아니다

아이가 우물거려서 못 알아들으면 `/stt`가 **`200` + `text: null`** 을 준다.
그대로 다음 화면으로 진행한다. 422(엔진 장애)와는 다르다 —
분기표는 위 **호출 상세** 참고.

### ⑤ 화면에 뜨는 문장과 재생되는 음성은 출처가 다르다

혼동하기 쉬운 지점이다.

| | 어디서 | 언제 |
|---|---|---|
| **문장(텍스트)** | 앱 번들 / `/pronunciation` 응답 | 화면에 들어올 때 이미 있는 것 |
| **음성(mp3)** | `/tts` 응답 | 🔊를 **탭한 그 순간** |

`/pronunciation`은 채점 결과만 준다 — 음성은 안 준다.
`/tts`는 음성만 준다 — 채점도 교정도 하지 않는다.

그래서 따라 말하기·발음 퀴즈 화면은 **들어올 때 음성을 부르지 않고**, 🔊를 탭할 때만 부른다.

## 지금 쓰이지 않는 API — `/feedback` · `/chat`

### `/feedback` (표현 교정) — 당분간 구현하지 않는다

"이렇게 말하면 더 자연스러워요"(④)와 피드백 배너(③)를 그리는 API인데,
**FastAPI 쪽에 만들지 않기로 했다.** 그래서 그 두 화면도 구현하지 않는다.

엔드포인트는 게이트웨이에 그대로 둔다 — 구현·테스트가 끝나 있어 유지 비용이 없고,
나중에 만들기로 하면 앱에서 부르기만 하면 된다.

> 앱 개발자에게: **지금은 `/feedback`을 구현하지 않아도 된다.**
> ②의 `/stt` 결과도 화면에 쓸 곳이 없어졌다 — 호출을 빼도 되고 남겨둬도 된다.

### `/chat` (자유 대화)

**목업 5개 어디에도 `/chat`을 부르는 화면이 없다.**

`/chat`은 자유 대화용이다 — 아이가 무슨 말을 할지 모를 때 STT + LLM + TTS를 한 번에 돌린다.
지금 시안은 전부 "정해진 문장 따라 말하기"라 `/stt` + `/pronunciation` + `/pronunciation/sentences` + `/tts`만 쓴다.

명세 §7에는 자유 대화 화면이 있는 것으로 되어 있지만, **현재 자유 대화 화면을 추가할
계획은 없다** (기획 확인 완료). 따라서 `/chat`은 당분간 호출되지 않는다.

**엔드포인트는 그대로 둔다.** 이미 구현·테스트가 끝나 있어 유지 비용이 없고,
나중에 자유 대화 화면이 생기면 앱에서 부르기만 하면 된다.
지우면 그때 명세·코드·테스트를 다시 만들어야 한다.

> 앱 개발자에게: **지금은 `/chat`을 구현하지 않아도 된다.** 시나리오 4개 모두
> `/stt` + `/pronunciation` + `/pronunciation/sentences` + `/tts` 네 개로 끝난다.

## 와이어프레임에 표기하는 방법

시안 이미지에 긴 설명을 넣으면 읽기 어렵다. **번호만 달고 이 문서를 참조**하는 편이 낫다.

```
화면 옆에:   ★ POST /stt
             ★ GET /pronunciation/sentences
             ★ POST /pronunciation
             ★ POST /tts (KOREAN)
```

Figma를 쓴다면 각 버튼에 **코멘트**로 API 이름만 달고, 상세는 이 문서 링크를 건다.
요청 필드가 바뀌면 이 문서만 고치면 되고 시안은 그대로 둘 수 있다.
